10. Put the page in the address bar

This lesson puts the shelf in the browser history. The page number and the sort are the query string, so the address is the state of the list and can be sent to someone else. A click still swaps only the shelf. Opening that address, reloading, or pressing Back restores the whole lesson. HTMX marks a Back/Forward refetch with HX-History-Restore-Request.

Try it

{% include "tutorial/shelf.html" %}

What changed

Each link has a normal href and the same hx-get, target, and innerHTML swap you already know. The new attribute is hx-push-url="true". After the swap, the address becomes that link's URL. Five books are on a page. Next asks for the next five. Sort by author asks for the first page in author order. The lesson text stays outside #shelf, so it is not replaced.

The markup and the two responses

<a
  href="/ui/tutorial/10?page=2&ordering=title"
  hx-get="/ui/tutorial/10?page=2&ordering=title"
  hx-target="#shelf"
  hx-swap="innerHTML"
  hx-push-url="true"
>Next</a>

GET /ui/tutorial/10 renders this whole lesson when you open the address yourself. When HTMX asks, it renders only tutorial/shelf.html. Pressing Back asks again, and HTMX adds HX-History-Restore-Request. That request gets the whole lesson, not the shelf. A shelf-only response would replace the window.

Request, response, target, swap

  • Request: GET /ui/tutorial/10?page=...&ordering=.... HTMX sends HX-Request. Back and Forward also send HX-History-Restore-Request.
  • Response: the shelf fragment for a click. The full lesson for a new tab, a reload, or Back/Forward.
  • Target: #shelf on a click. Back/Forward targets the page.
  • Swap: innerHTML on a click. hx-push-url is not a swap. It writes the address.

Experiment

Click Next. The address changes and this explanation stays. Copy that address into a new tab: you get the whole lesson, already on that page. Come back and press the browser Back button. You should land on the first page of this lesson, not on a bare list.
