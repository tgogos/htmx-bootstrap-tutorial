12. Load the list when it reaches the screen

Lesson 5 started a request from a menu. This box starts a request when you scroll it into view. Until then the titles are not in the page.

Try it

Scroll down. The bordered box fetches the first few titles the moment it reaches the screen.

Keep scrolling. The next box is the one that fetches.

This box loads a few titles when it reaches the screen.

What changed

The new attribute is hx-trigger="revealed". HTMX watches the box and sends the request the first time any of it is on screen. There is no button. The box is its own target, and innerHTML replaces the sentence inside it with the titles. Scrolling away and back does not ask again. The empty space above the box is only so the box starts off screen. A box that is already visible loads at once.

The markup and the fragment

<div
  id="lazy-books"
  hx-get="/ui/tutorial/12/books"
  hx-target="#lazy-books"
  hx-swap="innerHTML"
  hx-trigger="revealed"
>...</div>

GET /ui/tutorial/12/books is lesson_lazy_books in app/ui/tutorial_routes.py. It returns tutorial/lazy_books.html: the first five titles, in title order. It sleeps for one second first, and the fragment says that wait is artificial, so the placeholder stays readable. This URL is only that list. It is not the books table, and it does not change the address.

Request, response, target, swap

  • Request: GET /ui/tutorial/12/books when the box reaches the screen.
  • Response: a short list of titles.
  • Target: #lazy-books, the box itself.
  • Swap: innerHTML.

Experiment

In the inspector, set hx-trigger="click" and reload. The box waits until you click it. Set revealed again, scroll so the box is already on screen, and reload. The request starts at once, because a box that is already visible counts as revealed. The one-second wait is still there.
