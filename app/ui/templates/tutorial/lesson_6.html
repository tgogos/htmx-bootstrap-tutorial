6. Search as you type

Lesson 5 waits until you finish choosing. A search box should update while you type, but not on every key, and not with an answer for a query you have already moved past.

On this page a one-letter search is held for 1.2 seconds on purpose, so the left box can show that list before the longer one. The books list does not sleep.

Try it

This box lets the current search finish, then runs the new one.

This box drops an in-flight search when you type again.

HTMX 4 queues the next search on the left until the one in flight finishes, so the list you end on matches the box. The right box cancels that in-flight search, so the one-letter list never appears.

What changed

The new piece on both boxes is hx-trigger. keyup changed delay:300ms waits until you pause, and it skips the request when the text did not change (arrow keys, for example). The search event covers the clear button on a search field. With no hx-sync, HTMX 4 uses queue first: the new search waits until the current one finishes. You see the older list, then the newer one replaces it. The list you end on matches the text in the box.

The right-hand box adds hx-sync="this:replace". That aborts the search already running and starts the new one, so the one-letter list never appears. That is the version to keep for a search box. drop is the other choice: ignore a new request while one is running.

The markup

<input
  type="search"
  name="q"
  hx-get="/ui/tutorial/books?slow=1"
  hx-trigger="keyup changed delay:300ms, search"
  hx-target="#fresh-results"
  hx-swap="innerHTML"
  hx-sync="this:replace"
>

The route is still lesson_book_list. name="q" adds the text you typed. slow=1 is only for this lesson: a query of one character sleeps 1.2 seconds, and the fragment says so. A longer query does not sleep. hx-sync is not a parameter of this function. A cancelled request never reaches it. The input stays outside the target, so the response cannot wipe out the letters you are still typing.

query = (q or "").strip() or None
if slow and query is not None and len(query) <= 1:
    await asyncio.sleep(1.2)
return templates.TemplateResponse(
    request, "tutorial/book_list.html", {"books": books, "delay": delay, ...},
)

Request, response, target, swap

  • Request: GET /ui/tutorial/books?slow=1&q=... after a 300ms pause.
  • Response: the title list. A one-letter search also includes the artificial-wait line.
  • Target: the results element under that box, not the input.
  • Swap: innerHTML. hx-sync is not a swap. With none set, the next request waits. this:replace cancels the one in flight.

Experiment

In the left box, type d and pause until the request has started, about half a second. Then type une and pause. The one-letter list appears first, with the artificial-wait line. Then the Dune list replaces it: the second search waited. Do the same in the right box. The one-letter list does not appear, and Dune stays.
