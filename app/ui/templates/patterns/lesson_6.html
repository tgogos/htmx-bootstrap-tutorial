6 · Export

Export selected starts a job for the checked books. A bar asks the server again until the job is finished, the same kind of trigger as lesson 13.

{% include "patterns/stage.html" %} {% if can_edit %}
{% endif %}

What changed

Lesson 13 puts every on the box. innerHTML replaces only the inside, so the trigger stays and the clock never stops. Here the button is outside the form. It posts the checked ids with hx-include="#pattern-form", and the answer lands in the empty #export-job, not in the table.

The fragment that comes back carries hx-trigger="every 1s" and targets that same box. Each answer replaces the fragment. The last answer has no every, so nothing is left to ask again. The books stay as they are.

POST /ui/patterns/6/export remembers the checked titles for this browser and returns the bar at 0%. Each GET to that address adds one step, 25% then 50%, 75%, and 100%, and then forgets the job. No file is written, and the request does not wait.

The markup

<button
  type="button"
  hx-post="/ui/patterns/6/export"
  hx-include="#pattern-form"
  hx-target="#export-job"
  hx-swap="innerHTML"
>Export selected</button>
<div id="export-job"></div>

The first answers still ask again:

<div
  id="export-progress"
  hx-get="/ui/patterns/6/export"
  hx-trigger="every 1s"
  hx-target="#export-job"
  hx-swap="innerHTML"
>25%</div>

The last answer is the same bar at 100%, with those attributes gone:

<div id="export-progress">100%</div>

Because the trigger lived on the fragment, replacing the fragment removes the trigger. On lesson 13 the trigger lives on the box, so a new sentence inside it cannot stop the clock.

Request, response, target, swap

  • Request — POST /ui/patterns/6/export, then GET /ui/patterns/6/export once a second
  • Response — the bar, then the same bar a step further
  • Target — #export-job
  • Swap — innerHTML

Try this

Check one or two books and click Export selected. Watch the bar reach 100%, then stop. The books are unchanged.
