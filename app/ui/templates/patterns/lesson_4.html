4 · Morph

The new table is merged into the one already on the page. A check you did not mean to clear can stay.

{% include "patterns/stage.html" %}
The count line is still outside the table. Refresh does not send the extra fragment from pattern 3, so that line can stay old. This page is only about the checks.

What changed

Patterns 2 and 3 use hx-swap="innerHTML". That drops the old table and builds a new one, so every box comes back empty. This page uses hx-swap="innerMorph". HTMX edits the table already on the page until it matches the new HTML. A row and a box keep the same id, so the check you set is still that box.

The markup

<form id="pattern-form" hx-post="/ui/patterns/4/mark" hx-target="#pattern-board" hx-swap="innerMorph">
  <button type="button" hx-get="/ui/patterns/4/table" hx-target="#pattern-board" hx-swap="innerMorph">
    Refresh
  </button>
  <tr id="pattern-row-…">
    <input type="checkbox" id="select-…" name="book_id" value="…">
  </tr>
</form>

Refresh is type="button" and hx-get. It does not submit the form, so the checked ids are not sent. The response is the same row and the same box, with no checked:

<tr id="pattern-row-…">
  <input type="checkbox" id="select-…" name="book_id" value="…">
</tr>

innerMorph finds id="select-…" and keeps the check you set in the browser. innerHTML would throw that box away, and the new one would arrive empty.

Request, response, target, swap

  • Request — GET /ui/patterns/4/table for Refresh, or POST /ui/patterns/4/mark for the mark buttons
  • Response — the same table
  • Target — #pattern-board
  • Swap — innerMorph

Try this

Check two books and click Refresh. The badges stay as they were, and the checks stay too. On pattern 2, the same kind of replacement clears them.
