14. A form hears a search box and a menu

Lesson 13 puts the trigger on the same element that asks. This form asks, and the trigger names two other controls: the search box and the category menu.

Try it

Matching titles will appear here.

What changed

The new piece is from: on hx-trigger. hx-get, hx-target, and hx-swap sit on the form. The search box and the menu have no hx- attributes of their own. A form's default trigger is submit, and this form has no submit button, so the written trigger is what starts the request.

change from:select[name='category'] hears the menu. keyup changed delay:300ms from:input[name='q'] hears the search box after the same pause as lesson 6, and it skips a key that did not change the text. search from:input[name='q'] hears the clear button on that box. Because the form owns the request, both name="q" and name="category" go on the URL together. A category chosen after a search stays in the next search, and the text stays when you change the menu.

The markup and the fragment

<form
  hx-get="/ui/tutorial/books"
  hx-target="#catalog-results"
  hx-swap="innerHTML"
  hx-trigger="change from:select[name='category'], keyup changed delay:300ms from:input[name='q'], search from:input[name='q']"
>
  <input type="search" name="q">
  <select name="category">...</select>
</form>

The route is still lesson_book_list, the same one lessons 5 and 6 call. It already reads q and category, and it renders tutorial/book_list.html: a short list of titles, not the books table. The form stays outside #catalog-results, so the response cannot wipe out the letters you are still typing or the category you chose.

category: str | None = Query(None),
q: str | None = Query(None),

Request, response, target, swap

  • Request: GET /ui/tutorial/books?q=...&category=... when the menu changes, or after a pause in the search box.
  • Response: an HTML list of matching titles.
  • Target: #catalog-results. The form is not the target.
  • Swap: innerHTML. from: is not a swap. It names the element that fires the form's request.

Experiment

In the inspector, delete hx-trigger from the form. Type in the search box, and change the menu. Nothing fetches: a form waits for submit, and this form has no submit button. Put the trigger back. Then delete only the change from:select[name='category'] clause and change the menu. The search box still updates the list. The menu does not, until you put that clause back.
