3. A slow request needs a signal

Lesson 2 returns immediately, so you never see a wait. This button calls the same card route with ?delay=1.5. The server sleeps on purpose. hx-indicator points at the element HTMX shows while that request is in flight.

The wait is only on this tutorial URL. The books list does not sleep.

What changed

The button is the lesson 2 button, with two additions: the URL asks the card route to wait, and hx-indicator="#lesson-indicator" names the spinner. During the request HTMX adds htmx-request to that element. The stylesheet fades it in. When the response arrives, HTMX removes the class and swaps the card into #book-slot, same as lesson 2.

The markup and the wait

{% if book %} 
<button
  type="button"
  hx-get="/ui/tutorial/books/{{ book.id }}/card?delay=1.5"
  hx-target="#book-slot"
  hx-swap="innerHTML"
  hx-indicator="#lesson-indicator"
>Show {{ book.title }} slowly</button>

<span id="lesson-indicator" class="htmx-indicator">...</span>
{% endif %}

The route is still GET /ui/tutorial/books/<id>/card. delay is a query parameter capped at 5 seconds. After the sleep it renders the same tutorial/book_card.html fragment. The card says that the wait was artificial.

Request, response, target, swap

  • Request: GET the card URL with delay=1.5. The response is slow on purpose.
  • Response: the same card fragment as lesson 2, plus a line that names the wait.
  • Target: #book-slot. The spinner is not the target.
  • Swap: innerHTML. The indicator is separate: it is shown for the life of the request, then hidden.

Experiment

In the browser's inspector, delete hx-indicator from the button and click it again. The card still arrives, about a second and a half later, but nothing tells you the request is running.
