The checked ids are sent together. The response is this table again, and it replaces #pattern-board.

What changed

The form owns the request. hx-post, hx-target, and hx-swap sit on the form. The checkboxes have no hx- attributes of their own. A checked box is included because it is inside that form. An unchecked box is left out.

The markup

<p id="available-count">8 available</p>
<div id="pattern-board">
  <form
    hx-post="/ui/patterns/2/mark"
    hx-target="#pattern-board"
    hx-swap="innerHTML"
  >
    <button type="submit" name="available" value="1">Mark available</button>
    <button type="submit" name="available" value="0">Mark unavailable</button>
    <input type="checkbox" name="book_id" value="…">
  </form>
</div>

The button you click is a submit button, so its name and value go too: available=1 or available=0. One request carries that choice and every checked id. The response is this board again, with the badges updated and the boxes empty. innerHTML throws the old board away, which is why the checks clear.

#available-count sits outside #pattern-board. The swap never touches it, so the line still shows the old number.

Request, response, target, swap

  • Request — POST /ui/patterns/2/mark
  • Response — the same table, with the badges updated
  • Target — #pattern-board
  • Swap — innerHTML
