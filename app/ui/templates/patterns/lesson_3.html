3 · Out of band

The same mark action. The response also carries a second fragment, out of band, for the line above the table.

{% include "patterns/stage.html" %}

What changed

Pattern 2 left that line stale because it sits outside #pattern-board. Out of band means one response can update a second element, somewhere else on the page. The attribute is hx-swap-oob. The element carries the same id as the line already on the page, so HTMX knows where to put it.

The markup

The page is the one from pattern 2. The count is outside the board:

<p id="available-count"><strong>8</strong> available</p>
<div id="pattern-board">
  <form hx-post="/ui/patterns/3/mark" hx-target="#pattern-board" hx-swap="innerHTML">
    …
  </form>
</div>

The response is that form again, plus the count marked out of band:

<form hx-post="/ui/patterns/3/mark" hx-target="#pattern-board" hx-swap="innerHTML">
  …
</form>
<p id="available-count" hx-swap-oob="outerHTML"><strong>7</strong> available</p>

HTMX takes the paragraph out of the response and replaces the #available-count already on the page. outerHTML replaces the whole line. The form is what lands in #pattern-board, still with innerHTML, so the checks still clear.

Request, response, target, swap

  • Request — POST /ui/patterns/3/mark
  • Response — the table, plus the count line marked out of band with hx-swap-oob
  • Target — #pattern-board for the table. The count finds itself by id.
  • Swap — innerHTML for the table. outerHTML for the count.
