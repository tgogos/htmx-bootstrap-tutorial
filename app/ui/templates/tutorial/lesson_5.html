5. Let a control fire the request

Lessons 2–4 wait for a click, and they always ask for the same book. A menu can start the request when its value changes, and that value can go along with the request.

Try it

Titles in the chosen category will appear here.

What changed

The control is a select, not a button. hx-trigger="change" means "send the request when the choice changes." For a select, input, or textarea, that is already the default, so writing it out is for you to see. A button's default is click. The name="category" attribute is what puts the chosen value on the URL as ?category=fiction.

The markup and the fragment

<select
  name="category"
  hx-get="/ui/tutorial/books"
  hx-target="#category-results"
  hx-swap="innerHTML"
  hx-trigger="change"
>...</select>

GET /ui/tutorial/books is lesson_book_list. It reads category from the query string, because the menu's name is category, and it renders tutorial/book_list.html: a short list of titles, not the books table. The menu stays outside #category-results, so the response does not replace the control you are using.

category: str | None = Query(None)
chosen = (category or "").strip() or None
books, total = await books_repo.list_books(
    page=1, size=8, category=chosen, ordering="title",
)
return templates.TemplateResponse(
    request, "tutorial/book_list.html", {"books": books, ...},
)

Request, response, target, swap

  • Request: GET /ui/tutorial/books?category=... when the menu changes.
  • Response: an HTML list of matching titles.
  • Target: #category-results.
  • Swap: innerHTML, the same replacement as lesson 2.

Experiment

In the inspector, delete hx-trigger and change the category again. It still fetches, because change is the default for a menu. Then set hx-trigger="click" and open the menu: the request fires on the click, before you have picked a new category.
